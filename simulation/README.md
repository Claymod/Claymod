# Claymod TLS simulation

Verifies the mutual-TLS layer end-to-end with a control-side probe and a
real `claymod agent`, using PKI generated by claymod's own `internal/ca`
package.

## Topology

```
certgen ──writes──> /certs (volume)
                     │
agent   ──reads─── /certs, listens mTLS 0.0.0.0:2323
                     │
control ──reads─── /certs, dials agent:2323 (probes.sh)
```

All three are the same image (`simulation/Dockerfile`): the `claymod`
binary (control + agent) and `certgen` (PKI generator).

## What the probes assert

| # | Probe | Expected |
|---|---|---|
| 1 | Valid client cert (`control.pem`) | connect + Ping + Facts + Apply smoke (2nd pass = no-op) |
| 2 | Client cert from an untrusted CA (`rogue.pem`) | rejected |
| 3 | Trusted CA but wrong EKU (`wrong-eku.pem`, ServerAuth-only) | rejected |
| 4 | No client certificate (anonymous) | rejected (mTLS mandatory) |
| 5 | Probe verifies server against the rogue CA | rejected |

Any probe behaving unexpectedly fails the whole run.

## Run it

Docker mode (default):

```sh
simulation/run.sh
# or directly:
docker compose -f simulation/docker-compose.yml up --build --abort-on-container-exit
```

Local loopback mode (no Docker, same probe suite):

```sh
simulation/run.sh --local
```

## Files

- `Dockerfile` — build stage (Go 1.26) + alpine runtime
- `docker-compose.yml` — certgen → agent → control services
- `certgen/main.go` — PKI generator (uses `internal/ca`)
- `scripts/probes.sh` — the five TLS checks
- `run.sh` — orchestrator (docker + local modes)

Artifacts land in the `certs` volume (docker mode) or `.certs-local/`
(local mode); both are disposable and git-ignored.
